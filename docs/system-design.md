# Rendi Hall — system design

Дополняет [spec.md](spec.md): компоненты, поток данных, владение состоянием,
порядок кадра, деградация. Всё ниже — обязательно для агентов наравне со
спекой.

## 1. Требования (сжато)

**Функциональные:** ходьба (клавиши / клик / тап), близость к стендам и NPC,
открытие продукта с наездом камеры, чат-презентация по скрипту, waitlist,
обход без ходьбы, deep-link.

**Нефункциональные:** 60 fps на M1, приемлемо (≥ 30) на среднем Windows-ноуте
с интегрированной графикой; TTI < 3 с; работает офлайн после загрузки
(статика); не падает при отсутствии WebGL.

**Ограничения:** только статика (GitHub Pages); 6 параллельных агентов →
минимум общих файлов; Node вне PATH.

## 2. Компоненты

                         │        main.js           │  сборка, порядок кадра
                         └─────────────┬────────────┘
           ┌───────────────┬───────────┼──────────────┬────────────────┐
           ▼               ▼           ▼              ▼                ▼

   │ core/        │ │ world/     │ │actors/ │ │ stands/      │ │ ui/ (DOM)    │
   │ appState ◄───┼─┤ hall       │ │ randy  │ │ 7 модулей +  │ │ hud prompt   │
   │ events (bus) │ └────────────┘ │ npc    │ │ index        │ │ productView  │
   │ layout tokens│                └────────┘ └──────────────┘ │ chat bubble  │
   │ motion loop  │                                            │ skipList     │
   └──────┬───────┘   ┌──────────────────────────────┐         └──────┬───────┘
          │           │ systems/                     │                │
          │           │ input  movement  proximity   │                │
          │           │ cameraRig                    │                │
          │           └──────────────────────────────┘                │
          │                         ▲                                 │
          └──────── bus: события ───┴─────────────────────────────────┘

Правило зависимостей: любой модуль может импортировать `core/*`, `kit/*`,
`content/*`. Модули одного слоя друг друга **не импортируют** — только через
bus или через `main.js`, который передаёт ссылки.

## 3. Владение состоянием — `core/appState.js`

Единственный владелец режима приложения. Остальные модули **читают** режим и
**просят** переход событием; переход делает только appState. Это убирает
гонки (Esc во время наезда, двойной клик по стенду, клик по чипу во время
закрытия).

```
 BOOT ──► LOADING ──► EXPLORE ◄───────────────────────────┐
                        │  ▲                               │
          stand:open    │  │ stand:closed                  │
                        ▼  │                               │
                     OPENING ──stand:opened──► FOCUSED ──stand:close──► CLOSING
                        │                                                 ▲
                        └──────────── stand:close (Esc в полёте) ─────────┘
 любое ──webgl:lost / no-webgl──► FALLBACK
```

- `OPENING` прерываемо: `stand:close` во время наезда → таймлайн
  `reverse()` с текущей точки, переход в `CLOSING`.
- В `OPENING | FOCUSED | CLOSING` ввод движения игнорируется
  (`input` проверяет `appState.is('EXPLORE')`), NPC продолжают жить.
- Открытый продукт — `appState.focusedId`. Deep-link и skipList
  идут через тот же `stand:open`, отдельной ветки нет.

API: `appState.mode`, `appState.focusedId`, `appState.is(...modes)`,
`appState.request(event, payload)` → bool (false, если переход недопустим).
Под vitest — таблица переходов.

## 4. Порядок кадра (`core/loop.js`)

`dt = min(clock.delta, 1/30)` — после вкладки в фоне мир не «прыгает».

```
1. input.poll()                       клавиши → вектор; клик → цель
2. if EXPLORE: vel = input → movement.step(...) → randy.setVelocity
3. randy.update(dt); npcs.forEach(update)
4. proximity.update(randyPos)         → bus 'proximity:enter/leave' (гистерезис +0.3)
5. stands.forEach(s => s.update(t, dt, stateOf(s.id)))
6. cameraRig.update(dt)               follow-lerp в EXPLORE; в OPENING/CLOSING ведёт GSAP
7. ui.syncScreenAnchors()             чип над стендом, облачка NPC — через cameraRig.toScreen
8. renderer.render(scene, camera)
9. debug.update()                     только при ?debug
```

GSAP работает на собственном тикере, но `gsap.ticker.lagSmoothing(0)` и
рендер — только в шаге 8, без второго rAF.

## 5. Поток данных: открытие продукта

```
input(Enter) ─► bus 'stand:open'{id} ─► appState: EXPLORE→OPENING
                                          │
            ┌─────────────────────────────┼──────────────────────────┐
            ▼                             ▼                          ▼
     randy.wave()          cameraRig.focus(pose)        productView.open(id, toScreen(stand))
                           (GSAP 900ms)                  clip-path c 40% таймлайна
            └────────────── оба Promise resolved ───────────────────┘
                                          ▼
                     bus 'stand:opened' ─► appState: OPENING→FOCUSED
                                          ▼
                          chat.start(content.products[id].chat)
```

Кто ждёт кого: `main.js` слушает переход в `OPENING`, запускает три действия,
делает `Promise.all`, эмитит `stand:opened`. Закрытие — зеркально, с
`release()` и `productView.close()`.

## 6. Данные

- `content.json` импортируется статически (в бандл) — сетевой ошибки чтения нет.
- **Валидация на этапе тестов** (`tests/content.test.js`): у каждого продукта есть стенд в `layout.js` и модуль в `stands/`; у каждого `reply.to` есть узел; нет недостижимых узлов; у каждого графа есть путь к `action: "waitlist"`.
- `layout.js` — координаты, радиусы, waypoints NPC; стенды не хранят своих позиций.

## 7. Сбои и деградация

| Ситуация | Поведение |
|---|---|
| Нет WebGL | `FALLBACK`: DOM-версия — герой бренда + сетка карточек продуктов; клик открывает **тот же** `productView` + `chat` (без 3D слева). Концепт всё равно читается. |
| `webglcontextlost` | оверлей «Something hiccuped — reload» с кнопкой; `preventDefault` и попытка восстановления. |
| Медленный GPU | адаптивное качество (ниже). |
| Шрифты не загрузились | `font-display: swap`, фолбэк `system-ui`; лоадер ждёт `document.fonts.ready` не дольше 1.5 с. |
| Неизвестный `#/product/<id>` | игнор, обычный старт. |
| Ошибка в модуле стенда | `stands/index.js` оборачивает `build()` в try/catch → стенд-заглушка (пьедестал + табличка), остальное работает; ошибка в консоль. |

**Адаптивное качество:** первые 2 с после загрузки считаем средний кадр.
Если > 22 ms — по ступеням, с паузой 1 с между ними:
1) DPR → 1.5 → 1; 2) тени выкл. (тень-декаль под персонажами остаётся);
3) контуры с декора выкл. (на персонажах и стендах — никогда).
Ступень не откатывается обратно в течение сессии (без мигания).

## 8. Нагрузка и бюджеты

| Ресурс | Бюджет |
|---|---|
| JS (three + gsap + код) | ≤ 300 KB gz |
| Шрифты | 5 woff2, только latin, ≤ 120 KB |
| Текстуры | 0 файлов: gradientMap — `DataTexture` 2×1, узор паркета — геометрия/инстансы |
| Draw calls | ≤ 400 (≤ 8 на персонажа, ≤ 20 на стенд) |
| Треугольники | ≤ 150 k |
| Память GPU | ≤ 150 MB |

## 9. Наблюдаемость (dev)

`?debug` в URL: панель FPS / draw calls / triangles (`renderer.info`),
коллайдеры и радиусы близости как кольца на полу, текущий `appState.mode`.
Нужно агентам для самопроверки и мне — для приёмки по скриншотам. В прод-
сборке модуль не грузится (dynamic import по флагу).

## 10. Trade-offs и что пересмотреть

| Решение | Цена | Пересмотреть, когда |
|---|---|---|
| Без pathfinding (прямая + скольжение) | Randy может «упереться» в угол стенда при клике через препятствие | если клик-ходьба путается на ревью → A* по сетке 0.5u |
| Одна сцена, всё грузится сразу | время старта растёт с числом стендов | > 12 продуктов → комнаты + `import()` стендов по близости |
| Скриптовый чат | нет «живого» ответа | если заказчик захочет AI-гида — `chat` получает провайдера с тем же интерфейсом узлов |
| Контент в JSON в бандле | правка = пересборка | при реальном продукте → headless CMS |
| Один appState вместо state-машины на библиотеке | ручная таблица переходов | если режимов станет > 8 |
