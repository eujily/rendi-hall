# ADR-002: Экран продукта — один рендерер + DOM-оверлей с clip-path

**Status:** Accepted
**Date:** 2026-10-09
**Deciders:** Жека

## Context

В зале 6 продуктовых стендов + стойка Waitlist. Подход к стенду → продукт
раскрывается на весь экран с анимацией приближения; внутри — чат-презентация.
Нужна непрерывность пространства (shared-element ощущение), 60 fps,
доступный текст.

## Decision

Один WebGL-рендерер. Камера через GSAP-таймлайн наезжает на стенд так, что
диорама встаёт в левую половину кадра. Справа поверх canvas разворачивается
DOM-панель: `clip-path: circle()` из экранной проекции стенда → полный
прямоугольник правой половины. Чат — HTML.

## Options Considered

### Option A: Один рендерер + DOM-оверлей (выбрано)
| Dimension | Assessment |
|---|---|
| Complexity | Low–Med |
| Perf | High — нет второго контекста |
| A11y | High — текст в DOM, фокус-трап, Esc |

**Pros:** настоящая пространственная непрерывность; дёшево. **Cons:** нужна точная поза камеры на стенд (`focusPose`).

### Option B: Второй рендерер/сцена в модалке
| Dimension | Assessment |
|---|---|
| Complexity | Med–High |
| Perf | Med — два WebGL-контекста |

**Pros:** изоляция. **Cons:** разрыв пространства, дубли геометрии, сложнее синхронизация.

### Option C: Полностью DOM-страница продукта (картинка вместо 3D)
| Dimension | Assessment |
|---|---|
| Complexity | Low |
| Wow | Low |

**Cons:** теряется главный эффект «въезда» в мир.

## Trade-off Analysis

A даёт самый сильный визуальный эффект при наименьшей цене; единственный
риск — подбор `focusPose` на каждый стенд, он локален и проверяется скриншотом.

## Consequences

- Каждый стенд обязан экспортировать `focusPose` (см. spec §Контракты).
- Мобильная вёрстка (<768px): панель снизу (bottom sheet 60% высоты), диорама сверху.
- `prefers-reduced-motion`: наезд заменяется кроссфейдом ≤200ms.
